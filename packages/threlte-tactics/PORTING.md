# Porting log

Port of The Liquid Fire's Unity [Tactics RPG](https://theliquidfire.com/category/projects/tactics-rpg/)
tutorial (`packages/tactics-rpg`) to Threlte + SvelteKit. Conventions live in `AGENTS.md`.

The author's [blogtacticsrpg](https://github.com/theliquidfire/blogtacticsrpg) repo has one commit
per blog post (its "Part N" is our part N+1 up to Victory Conditions; Intro To A.I. had no commit),
and its last commit is identical to `packages/tactics-rpg`. Use it to see which files a part adds
and what they looked like at that point.

## Divergences

Every difference in the rules from Unity, and anything a player would notice: the bugs fixed (each
pinned by a test) and the quirks not reproduced.

| Where                         | What                                                                                                                                                                                                                                            | Why                                                                                                                               |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `InputController.ts`          | Fire1 = Enter/Space, Fire2 = Escape/Backspace, Fire3 unbound (Unity: left ctrl/alt/cmd, mouse).                                                                                                                                                 | Keyboard only; Unity's keys clash with browser shortcuts.                                                                         |
| `ValueChangeException`        | Modifiers with equal sort orders apply in the order they were added.                                                                                                                                                                            | JS sorts are stable; .NET's `List.Sort` isn't.                                                                                    |
| Floats                        | JS numbers are doubles. C#'s 32-bit float math is reproduced only where a truncation depends on it (`Rank.experienceForLevel`).                                                                                                                 |                                                                                                                                   |
| `ExperienceManager`           | A party whose levels are all equal shares the award evenly.                                                                                                                                                                                     | Unity's weights are 0/0 = NaN, so nobody gains anything.                                                                          |
| `TurnOrderController`         | Units with equal counters act in reverse order of `BattleController.units`.                                                                                                                                                                     | JS's sort is stable; .NET's isn't, so Unity's order for ties is arbitrary.                                                        |
| `WeaponAbilityPower`          | With no weapon equipped it falls back to the job's attack, as the blog describes; Unity throws. No ability in the game uses it.                                                                                                                 | Unity reads the missing weapon's features.                                                                                        |
| `Mana`                        | MP is clamped to the max MP.                                                                                                                                                                                                                    | Unity clamps it to the max _HP_, so regenerating could take MP over its max (e.g. `MP 24 / 23`).                                  |
| `ActionSelectionState`        | Confirming a locked ability does nothing.                                                                                                                                                                                                       | When every ability in a category is locked, Unity picks the first anyway, and the actor uses up its action failing to perform it. |
| `EndBattleState`              | Starts the battle over (a new `<Battle>`, with the same `Random`). Unity calls `Application.LoadLevel(0)`, but the project's build settings list no scenes, so in the editor that only logs an error and the game sits in `EndBattleState`.     | The blog's intent: "causes the scene to reload".                                                                                  |
| `CutSceneState`               | Listens to input whoever drives the actor. In Unity, when a computer-driven unit ends the battle, the outro ignores input, so it can never be read past (always so when the heroes lose).                                                       | Unity bug: the battle couldn't end.                                                                                               |
| `ComputerPlayer`              | An ability on itself (or on everyone) with nowhere to move: the unit stays put. Unity picks from the empty list, which throws.                                                                                                                  | Unity bug: the battle would be stuck.                                                                                             |
| `ComputerPlayer`              | When choosing by angle, the best option is picked even if every angle score is negative (more of the wrong units hit from behind than of the right ones from the front). Unity starts from 0, finds none, and throws. The same picks otherwise. | Unity bug: the battle would be stuck.                                                                                             |
| `Rogue Attack Pattern.prefab` | Its "Blind Or Drain" picker picks Blind or Drain. Unity's lists itself instead of Drain, so it always ends up picking Blind. `scripts/convert-unity.ts` corrects the data (`pickerFixes`), checking that Unity's is still what it corrects.     | Unity data bug: the enemy rogue never used Drain.                                                                                 |
| Music                         | Starts at the player's first key press (or click), when browsers allow sound; Unity's starts with the scene. Clips are AAC, not WAV.                                                                                                            | Browser autoplay policy; size (34 MB → 2 MB).                                                                                     |

## Translations

How the port expresses a Unity or C# mechanism. Behaviour is the same, at a glance for
presentation.

| Where                                   | What                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Why                                                                                               |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Lighting / colors                       | Gamma space mimicked (color management off, linear output).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Unity project uses Gamma color space.                                                             |
| `Lighting.svelte`                       | Skybox ambient approximated with ambient + hemisphere lights.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Tuned by eye against footage of the Unity build.                                                  |
| `Battle.svelte`                         | Default skybox → fixed CSS gradient behind the canvas.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | The battle camera never rotates.                                                                  |
| `UnitModel.svelte`                      | Hero and Monster prefabs are one component with a `model` prop.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | They differ only by body material.                                                                |
| `Point.ts`                              | Points are interned (`Point.of`), not structs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | `===` equality; usable as `Map` keys.                                                             |
| `CameraRig.svelte`                      | Snaps to its target once less than 1e-4 units away.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Unity lerps forever; this lets on-demand rendering idle.                                          |
| `LayoutAnchor.svelte.ts`                | Placements stay anchor fractions + offset that CSS resolves (`<PanelView>`); no rounding to whole pixels.                                                                                                                                                                                                                                                                                                                                                                                                                                                   | The browser measures; layouts survive window resizes.                                             |
| `UIImage.svelte`                        | Sliced sprites are drawn on a canvas at device resolution.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | CSS `border-image` leaves hairline seams at fractional scales.                                    |
| `UIText.svelte`                         | Arial from the system; Best Fit measures whole font sizes in the browser.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Unity's font rendering and metrics differ slightly.                                               |
| `ConversationPanelView.svelte`          | The arrow's bounce is a CSS animation (Unity's curve, via `linear()`); it restarts when the arrow reappears.                                                                                                                                                                                                                                                                                                                                                                                                                                                | Unity pauses and resumes the tween; CSS lets rendering idle.                                      |
| `ConversationController`                | `completeEvent` → `show()` returns a promise.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | One listener (the cut scene state) per conversation.                                              |
| `AbilityMenuPanelController`            | No pooling: `show` makes fresh entries. An entry that was never selected keeps the prefab's half-transparent outline, where a recycled Unity entry may have an opaque one.                                                                                                                                                                                                                                                                                                                                                                                  | DOM nodes aren't worth pooling.                                                                   |
| `AbilityMenuPanelControllerView.svelte` | Unity's layout groups and content size fitter → CSS flexbox; text heights come from the browser's Arial metrics.                                                                                                                                                                                                                                                                                                                                                                                                                                            |                                                                                                   |
| `BattleController`                      | Unity's static `ActionSelectionState.category` → `actionSelectionCategory`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | One per battle, not per process.                                                                  |
| `NotificationCenter`                    | One per battle (`BattleController.notifications`), passed to the objects that use it; `this.PostNotification(…)` → `notifications.postNotification(name, sender, args)`. Notifications are typed by name.                                                                                                                                                                                                                                                                                                                                                   | No module-level singletons.                                                                       |
| Features, items                         | An item is not a GameObject: `Equippable`/`Consumable` hold the item's `features`. Features target a unit (`FeatureTarget`, which has the components they use) instead of looking them up from a GameObject's parents, so `Equippable.onEquip(owner)` takes the wearer.                                                                                                                                                                                                                                                                                     | No scene hierarchy.                                                                               |
| `Random`                                | A seeded mulberry32 for the whole game, as Unity's lasts from one battle to the next (`?seed=` replays it all; the seed is logged). `value` is in [0, 1) (Unity's includes 1); the sequence isn't Unity's.                                                                                                                                                                                                                                                                                                                                                  | Replayable battles and deterministic tests.                                                       |
| `Unit`                                  | `stats`, `rank`, `status` and `equipment` are created with the unit; Unity's `UnitFactory` adds them as components. The rest are fields that `UnitFactory` sets, in Unity's order.                                                                                                                                                                                                                                                                                                                                                                          | Every unit has them.                                                                              |
| Ability components                      | Created with what Unity finds in the hierarchy: a range with its unit (`new ConstantAbilityRange(unit, { horizontal })`, Unity's `GetComponentInParent<Unit>()`), `FullAbilityArea` with the range (`GetComponent<AbilityRange>()`), hit rates, effects and powers with their unit and the battle's `notifications` and `random` (`new ATypeHitRate(unit, battle)`). Effects and powers also look up their ability and siblings: `new Ability(…)` attaches them (`attach`), as Unity's `Instantiate` wakes a prefab's components once its hierarchy exists. | No scene hierarchy.                                                                               |
| `Ability`                               | An ability's GameObject and its `Ability` component are one class whose fields are its components. Its child GameObjects (an effect each) → `ability.effects`, whose fields are their components (`hitRate`, `target`, `effect`). A unit's `GetComponentInChildren<Ability>()` (its attack) → `unit.attack`.                                                                                                                                                                                                                                                | No scene hierarchy.                                                                               |
| `Status`                                | Effects and conditions aren't GameObjects: `Status` keeps each effect's conditions in a list, and is queried by class (`getEffect`, `getConditions`, `getEffectOf`). They're created with the `Status` (its `owner` and `notifications`). `AddStatusFeature<T>`'s type argument → an `effectType` field.                                                                                                                                                                                                                                                    | No scene hierarchy.                                                                               |
| `destroy`                               | Like Unity's `Destroy`, a removed effect or condition is taken out at once but disabled later: in a microtask (Unity: at the end of the frame). So an effect that ends as a round begins still works for the rest of the rounds before the next turn, as in Unity.                                                                                                                                                                                                                                                                                          | Faithful to Unity's frame timing.                                                                 |
| `Info`                                  | Only `Info<T0, T1, T2>`, the one the game uses.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Unused one- and two-argument versions.                                                            |
| `InflictAbilityEffect`                  | Finds the status effect class by name in `statusEffectTypes` instead of by reflection.                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | No reflection over classes in JS.                                                                 |
| Ability prefabs                         | An ability prefab is data (`AbilityPrefab`: each component's class name and Inspector fields); `instantiateAbility` builds the components for a unit. `scripts/convert-unity.ts` generates them from the prefabs, sorting components by the C# class they derive from.                                                                                                                                                                                                                                                                                      | No prefabs.                                                                                       |
| `UnitFactory`                           | A missing unit, job or ability prefab throws. Unity logs an error and goes on with an empty GameObject, which the next step fails on.                                                                                                                                                                                                                                                                                                                                                                                                                       | Clearer failure.                                                                                  |
| `BattleOptions.spawnTestUnits`          | Tests can replace `InitBattleState`'s `SpawnTestUnits` (`#lib/testing/spawn.ts`) to put particular units in particular places.                                                                                                                                                                                                                                                                                                                                                                                                                              | Test seam; Unity's spawn is temporary code too.                                                   |
| `Stats.unit`                            | A unit's `Stats` know their unit, so `AutoStatusController` can find the `Status` of the stats whose HP changed (Unity: `stats.GetComponentInChildren<Status>()`).                                                                                                                                                                                                                                                                                                                                                                                          | No GameObjects.                                                                                   |
| Attack patterns                         | Data like ability prefabs (`AttackPatternPrefab`); its ability pickers refer to each other by GameObject name. `instantiateAttackPattern` builds them for a unit.                                                                                                                                                                                                                                                                                                                                                                                           | No GameObjects.                                                                                   |
| `BattleController.move`/`fire`          | Whether a state listens to input (Unity's `BattleState.AddListeners`: not while the computer drives the actor) is decided when the input arrives, not when the state is entered. The same, as no driver changes mid-state.                                                                                                                                                                                                                                                                                                                                  | One input path, no listener bookkeeping.                                                          |
| `AudioSequenceData.isScheduled`         | `startTime >= 0`, not Unity's `> 0`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Unity's audio clock is never 0 when a scene starts, but a browser's is until the first key press. |
